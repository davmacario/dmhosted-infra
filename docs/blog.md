# DMHosted Blog

**Goal**: personal blog, hosted in my homelab.

## Requirements

- Runs in Homelab, exposed publicly via Cloudflare tunnel
- Built with lightweight framework (small container images)
- Static website (dumbest possible)
- Built in CICD
- Code is public
- Deployed in gitops fashion ([ArgoCD](./argocd.md))
- Own domain (`dmhosted.com`)

### Framework selection

I like [Hugo](https://gohugo.io/).
It ticks the "ease of use" box + it seems well supported.
Also, it can be customized a bit down the line.

Hugo is what the Cloudflare docs are built with.

Alternatives:

- Jekyll
- Astro
- Eleventy

### Building and deploying

- Code lives in GitHub
- Using public GitHub CI runners (for free)
- Container image is a release

## Implementation

### First setup

First, install Hugo.
On MacOS, use homebrew:

```bash
brew install hugo
```

Next, initialize the repo.
It's going to be called `dmhosted-blog`, and the Hugo config will be Yaml.

```bash
hugo new site dmhosted-blog --format yaml
cd dmhosted-blog
git init
```

Then, add the theme as submodule.
For now, I'll use paperless:

```bash
git submodule add --depth=1 https://github.com/adityatelange/hugo-PaperMod.git themes/PaperMod
echo "theme: PaperMod" >> hugo.yaml
```

Then, create a `.gitignore` (see [here](https://github.com/github/gitignore/blob/main/community/Golang/Hugo.gitignore)):

```gitignore
# Generated files by hugo
/public/
/resources/_gen/
/assets/jsconfig.json
hugo_stats.json

# Executable may be added to repository
hugo.exe
hugo.darwin
hugo.linux

# Temporary lock file while building
/.hugo_build.lock
```

As a sanity check, run the following and visit the displayed URL with your browser:

```bash
hugo server
```

This should show an empty page with only the title "My New Hugo Project".

Hugo has a predefined directory structure, see [docs](https://gohugo.io/getting-started/directory-structure/).
At this stage, we can configure the contents of `archetypes/default.md`, which is going to be used as default template
for new posts.

```markdown
---
date: "{{ .Date }}"
draft: true
title: '{{ replace .File.ContentBaseName "-" " " | title }}'
summary: ""
tags: []
---
```

> [!note]
>
> It is possible to use a different archetype for different types of content (identified by the directory they are
> placed in).
> For example, if posts are going to be placed in `content/posts/`, you can add an `archetypes/posts.md` as template
> for any new file in that directory.

### Adding content

To add new content (in `content/posts/`):

```bash
hugo new content posts/my-new-post.md
```

### License selection

- CC BY 4.0 for content
- MIT for code

Can add a reference to it by adding the following (picked up by PaperMod) in `hugo.yaml`:

```yaml
params:
  footer:
    text: 'Content <a rel="license" href="https://creativecommons.org/licenses/by/4.0/">CC BY 4.0</a> · Code <a href="https://github.com/davmacario/dmhosted-blog/blob/main/LICENSE">MIT</a>'
```

Indeed, looking at `themes/PaperMod/layouts/_partials/footer.html` (submodule), it is possible to see:

```html
<footer class="footer">
    {{/*
      ... other stuff
    */}}

    {{- with site.Params.footer.text }}
        {{ . | markdownify }}
        {{- print " · "}}
    {{- end }}

    {{/*
      ...
    */}}
</footer>
```

meaning that the contents of `params.footer.text` will be "markdownified" and placed as part of the footer.

### Container setup

Simply using Caddy to expose the static content generated by Hugo (`public/` directory created running build).

### CI/CD setup

Using GitHub workflows (free tier is enough) to publish (public) container image and do some sanity checks.

#### 1. Pipeline on main

- Builds and publishes container images
- Needs read permissions on contents, write on packages
- Steps:
  1. Checkout
  2. Install Hugo
  3. Build (`hugo --minify --gc`)
  4. Upload artifact (`public/` created by the previous step)
  5. Log into GHCR from pipeline (using `${{ secrets.GITHUB_TOKEN }}`)
  6. Derive tags for container image
  7. Build + push container image

#### 2. Pipeline on PR

- Used to run hugo build (sanity check) + check for broken links + validate caddyfile
- Steps:
  1. Checkout
  2. Install Hugo
  3. Build
  4. Check broken links using `https://github.com/wjdp/htmltest`
  5. Validate caddyfile (launch container)
  6. Verify image builds
  7. Upload artifacts (for testing)
